# myway 复利变现规划

> 目标:把 myway 从"一个开源 fork"变成"持续产生被动收入的复利资产"。
> 原则:不做"卖时间"的接单,做"做一次、卖无数次"的资产。
> 诚实前提:复利前期(2–3 个月)可能 0 收入,但后期滚起来后是被动增长。

---

## 〇、执行摘要(TL;DR)

myway 直接卖钱走不通(免费竞品 Vimium 百万用户)。但它有 **3 个真资产**,
能通过 **3 条复利路径** 变现:

| 资产 | → 变现路径 |
|------|-----------|
| 深度技术案例(读懂 Vimium 架构 + 改造) | **路径 ① 内容复利** |
| 多端打包工程化(`build_scripts/`) | **路径 ② 开发者工具** |
| 可视化编辑器 + 缺失的 Pro 能力 | **路径 ③ 订阅产品** |

**组合打法(核心)**:三条路是一条漏斗,不是三选一 ——
```
内容(流量入口) → 工具(中期变现) → 订阅(长期被动收入)
```

**90 天里程碑**:见文末「四、90 天行动表」。

## 一、资产盘点:myway 手上到底有什么真东西

> 这是写规划前必须认清的事实。我读过你的代码,以下是**能变现的真资产**。

### 1.1 深度技术内容素材(✅ 已有,可直接写成内容)

| 素材 | 在代码里的体现 | 能写成什么内容 |
|------|--------------|--------------|
| Manifest V3 全套实战 | `manifest.json`:service worker、content script、9 项权限 | "MV3 插件开发实战"系列 |
| Vimium 架构级改造 | `background_scripts/`(mode/handler_stack/completer) | "我是怎么读懂两万行 Vimium 的" |
| 多端打包工程化 | `build_scripts/build.js`:一套源码出 3 个 zip | "Chrome/Edge/Firefox 三端打包" |
| 可视化编辑器 | `pages/keybindings.*`(按键录制器) | "手撸一个可视化快捷键编辑器" |
| 冲突键治理 | `build_scripts/check.js` 里的移除绑定检查 | "插件快捷键冲突怎么治" |

### 1.2 可复用的工程化系统(✅ 已有,可抽成产品)

`build_scripts/` 里已经是一套成熟方案,稍作抽象就能卖:
- `build.js` — 多目标打包
- `check.js` — 静态校验(manifest 完整性、品牌一致性)
- `build_icons.js` — SVG→PNG 栅格化(sharp)
- `capture_screenshots.js` — 自动截图(puppeteer-core)
- `build_store_assets.js` — 商店素材生成
- `finalize.js` — 发布前收尾

> 这套东西,别的插件开发者要从零搭 1–2 周。**这就是产品。**

### 1.3 原创差异化(✅ 部分,需补强)

- 已有:可视化快捷键编辑器(Vimium 没有)
- 需补:云同步、工作流宏等(Vimium 也没有,且是真痛点)

## 二、三条复利路径详解

### 路径 ① 内容复利(⭐ 推荐第一步启动)

**本质**:把开发 myway 的过程做成内容,持续获得搜索流量 + 建立专业人设。

#### 2.1.1 平台与定位
- **主阵地**:掘金(技术深度) + 公众号(私域沉淀)
- **流量阵**:知乎(长尾搜索) + 小红书(泛开发者) + B站(可选,视频)
- **人设**:「专注浏览器扩展开发 / Vimium 深度玩家」—— 标签要窄而深

#### 2.1.2 系列选题(已按 myway 真实代码设计,可直接写)

**P1 启动篇(引流,低门槛):**
1. 《2026 年了,Manifest V3 浏览器插件到底怎么开发》
2. 《我 fork 了 Vimium,做了这 4 个改进》
3. 《Chrome/Edge/Firefox 三端插件,一套代码怎么打包》

**P2 深度篇(建权威,涨粉):**
4. 《我是怎么读懂 Vimium 两万行代码的(架构拆解)》
5. 《手撸一个可视化快捷键编辑器》
6. 《浏览器插件 9 项权限怎么申请才不被拒审》

**P3 变现篇(为路径②③铺垫):**
7. 《我开源了一套插件多端打包脚手架》→ 引流到工具
8. 《给 Vimium 加上云同步是什么体验》→ 引流到订阅

#### 2.1.3 复利机制
- 每篇都是长尾资产,持续来搜索流量(掘金/知乎 SEO 持续生效)
- 文章互链,流量在系列内滚动
- 公众号沉淀私域,后续推产品有基础

#### 2.1.4 变现方式
| 方式 | 何时启动 | 收入级别 |
|------|---------|---------|
| 平台流量分成/赞赏 | 写完即有 | 小,几十/月 |
| 公众号接广告 | 粉丝 1000+ | 几百–几千/篇 |
| 导流付费产品(路径②③) | 产品就绪后 | 主力收入 |

#### 2.1.5 KPI
- 90 天目标:发 8–10 篇,掘金粉丝 300+,公众号 200+
- 看不看得到钱:前 1 个月可能只有赞赏几十元,**这是正常的**,别在第 1 个月放弃

### 路径 ② 开发者工具变现(⭐ 中期主力变现)

**本质**:把 `build_scripts/` 抽成「插件开发脚手架模板」,卖给其他开发者。

#### 2.2.1 产品形态
**一个开箱即用的浏览器插件脚手架(starter / template):**
```
myway-starter(或改名)
├── manifest 三端模板(chrome/edge/firefox)
├── 一键打包:node build → 3 个 zip
├── 静态校验:check 脚本
├── 图标栅格化:SVG → PNG
├── 自动截图 + 商店素材
├── 隐私政策 / 权限说明模板
└── README 上架指引
```
**价值主张**:「省掉你 1–2 周搭工程化的时间,¥X 一套,复制即用。」

#### 2.2.2 卖点文案(核心)
> 「一个浏览器插件从开发到上架 3 个商店,工程化部分平均要 1–2 周。
> 这个脚手架把我上线级项目的全套构建系统抽出来了 —— 打包、校验、图标、
> 截图、素材、合规文档,全自动化。复制即用,省你 40+ 小时。」

#### 2.2.3 定价与渠道
- **Gumroad**:海外,$9–19(开发者付费意愿高,美元结算)
- **独立站 / 微店**:国内,¥39–69
- **License**:个人版(¥39) + 商用版(¥199,带技术支持)
- **复利点**:做一次,卖无数次,边际成本接近 0

#### 2.2.4 风险与对策
- ⚠️ 注意 MIT 传染:脚手架里 Vimium 衍生代码要标清来源,或**只抽工程化脚本、不抽 Vimium 业务代码**,规避争议
- ⚠️ 防盗版:核心是"持续更新 + 技术支持",别指望靠代码加密

### 路径 ③ 订阅产品(⭐⭐⭐ 天花板最高,周期最长)

**本质**:给 myway 补上 Vimium 缺失、且是真痛点的 Pro 功能,订阅制。

#### 2.3.1 关键认知
myway 现在只有"可视化编辑器"一个差异化点,**不够让 Vim 党付费**。
必须补上"没有就不行"的硬功能。

#### 2.3.2 Pro 功能优先级(按"付费意愿 × 实现难度"排序)

| 优先级 | Pro 功能 | 付费意愿 | 难度 | 为什么值钱 |
|--------|---------|---------|------|-----------|
| ⭐⭐⭐ | **设置云同步** | 高 | 中 | 多设备用户多年痛点,Vimium 没解决 |
| ⭐⭐⭐ | **工作流宏** | 高 | 中高 | 录制一连串操作一键执行,强差异化 |
| ⭐⭐ | **团队配置共享** | 高(企业) | 高 | 公司统一快捷键,企业付费单价高 |
| ⭐⭐ | **AI 划词/摘要** | 中高 | 中 | 当下热点,易做差异化 |

#### 2.3.3 定价
- 个人:¥19/年 或 ¥69 买断
- 团队:¥199/年起

#### 2.3.4 落地路径
1. 先做**云同步**(最高优先级,后端简单:键值存储即可)
2. 上架三端商店(已有 `store/PUBLISHING.md`)
3. 内容(路径①)养好的流量导过来
4. 观察转化,再决定补宏 / AI

## 三、组合漏斗(三条路怎么串起来)

```
                    ┌─────────────────────────────┐
   搜索流量 ───────▶ │  路径① 内容(掘金/知乎/公众号) │
                    └──────────────┬──────────────┘
                                   │ 沉淀专业人设 + 私域
                                   ▼
                    ┌─────────────────────────────┐
   开发者 ─────────▶ │  路径② 工具(脚手架 ¥39–199)  │ ← 中期变现主力
                    └──────────────┬──────────────┘
                                   │ 工具用户 = 高意向用户
                                   ▼
                    ┌─────────────────────────────┐
   终端用户 ───────▶ │  路径③ 订阅(Pro ¥19/年起)    │ ← 长期被动收入
                    └─────────────────────────────┘
```

**为什么这么排**:内容养流量(免费)→ 工具变现(低门槛,开发者爱买)→
订阅收口(高 LTV)。每一层都在给下一层导流。

## 五、风险与底线

| 风险 | 对策 |
|------|------|
| **第 1 个月没收入想放弃** | 这是复利的正常曲线,看 90 天,不看 30 天 |
| **MIT 传染争议** | 脚手架只抽工程化脚本,不抽 Vimium 业务代码;保留所有致谢 |
| **工具被白嫖/盗版** | 核心竞争力是"持续更新 + 支持",不靠加密 |
| **订阅没人买** | 先用内容验证需求,有热度再做,别闭门造车 |
| **精力跟不上** | 每周上限 8 小时,宁可慢,不要停。**持续 > 爆发** |

### 底线(随时可回退的退路)
如果 90 天后三条路都没起色:
- 退回接单(用 myway 当作品集,见 `FREELANCE_PITCH.md`)
- 但内容资产和工具不会消失,放着也会持续来少量流量
